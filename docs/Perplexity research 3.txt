localStorage vs Supabase: Strategic Decision for Beta
Direct answer: Switch to Supabase now, even for beta. Here's why and how:

1. When localStorage Becomes Problematic
localStorage breaks at:
User count: N/A — The issue isn't user count, it's use case:

Scenario	localStorage Viable?	Why
Single-device demo	✅ Yes	User never switches devices
Multi-device usage	❌ No	Data doesn't sync
Beta user feedback	❌ No	You can't see their data to debug
Longitudinal tracking	❌ No	Data lost if user clears cache
Pattern analysis	❌ No	Can't query across users
A/B testing	❌ No	Can't compare cohorts
For your VCM diagnostic app: localStorage fails immediately because:

You need to see diagnostic patterns across users to validate the VCM model

Hume.ai results should be backed up (expensive to re-process)

Recommendation engine learning requires cross-session queries

Users will switch devices (practice on laptop, review on phone)

Beta = iteration — you'll want to inspect user data without asking them to export JSON

localStorage-only red flags for your app:

2. Minimal Supabase Schema for Beta
Core Principle: Model your domain, not your UI
Start with these 4 tables:

sql
-- 1. Users (handled by Supabase Auth, but extend with profile)
CREATE TABLE user_profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  -- User-stated goals (Constraint 2: Desire)
  stated_goals TEXT[],  -- e.g., ['public_speaking', 'reduce_fillers']
  focus_areas TEXT[],
  
  -- Preferences
  preferred_session_length INTEGER DEFAULT 15,  -- minutes
  
  -- Metadata
  onboarding_completed BOOLEAN DEFAULT FALSE,
  last_active_at TIMESTAMPTZ
);

-- 2. Practice Sessions (core event log)
CREATE TABLE practice_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES user_profiles(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  -- Session metadata
  duration_seconds INTEGER,
  session_type TEXT,  -- 'free_practice', 'guided_drill', 'assessment'
  
  -- Performance metrics (local/immediate)
  word_count INTEGER,
  filler_word_count INTEGER,
  words_per_minute DECIMAL,
  
  -- Audio/transcript
  transcript TEXT,
  audio_url TEXT,  -- If storing audio in Supabase Storage
  
  -- Status
  completed BOOLEAN DEFAULT TRUE,
  abandoned_reason TEXT
);

-- 3. Session Analyses (Hume.ai + VCM diagnostics)
CREATE TABLE session_analyses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id UUID REFERENCES practice_sessions(id) ON DELETE CASCADE,
  user_id UUID REFERENCES user_profiles(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  -- VCM Diagnostic Results
  failed_gate TEXT,  -- 'A', 'B', 'C', or NULL
  failed_constraint TEXT,  -- 'C0', 'C1', ..., 'C6B'
  root_cause TEXT,
  constraint_scores JSONB,  -- Full ConstraintScore[] array
  confidence DECIMAL,
  
  -- Hume.ai Results (prosody/expression)
  hume_results JSONB,  -- Store full Hume response
  -- Extracted key metrics for querying:
  avg_stress DECIMAL,
  avg_confidence DECIMAL,
  avg_engagement DECIMAL,
  
  -- Metadata
  analysis_version TEXT DEFAULT 'v1'  -- Track diagnostic algorithm version
);

-- 4. Recommendations (for learning/adaptation)
CREATE TABLE recommendations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES user_profiles(id) ON DELETE CASCADE,
  session_id UUID REFERENCES practice_sessions(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  -- What was recommended
  exercise_id TEXT,
  target_constraint TEXT,
  recommendation_type TEXT,  -- 'USER_ALIGNED' | 'SYSTEM_DIAGNOSED'
  
  -- How it was presented
  presentation_style TEXT,  -- 'SUBTLE' | 'LIGHT_EXPLANATION'
  position_in_queue INTEGER,
  
  -- User response
  user_action TEXT,  -- 'ACCEPTED' | 'IGNORED' | 'DISMISSED' | 'COMPLETED'
  action_timestamp TIMESTAMPTZ,
  time_to_decision_ms INTEGER,
  completion_quality DECIMAL,
  
  -- Context (for learning)
  features JSONB  -- Store all learning features as JSON
);
Why this schema:
Normalized — Sessions separate from analyses (can re-analyze old sessions with new algorithms)

Queryable — Key metrics extracted from JSONB for fast queries

Extensible — JSONB columns for data that may evolve (Hume results, features)

Cascading deletes — User deletion removes all their data (GDPR-friendly)

Version tracking — analysis_version lets you compare diagnostic algorithms

CREATE TABLE practice_sessions (
  -- ... core fields ...
  
  -- Voice-specific (populated now)
  transcript TEXT,
  audio_url TEXT,
  
  -- Future: Text-specific (NULL for now)
  text_submission TEXT,
  
  -- Future: Video-specific (NULL for now)
  video_url TEXT,
  frame_analysis_url TEXT
);
Decision rule: If adding a new practice type requires <3 new columns, add them as nullable. If it needs 5+ columns, create a separate table with a foreign key to practice_sessions.

4. Row-Level Security (RLS) for Practice Sessions
Basic RLS Setup
sql
-- Enable RLS on all tables
ALTER TABLE user_profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE practice_sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE session_analyses ENABLE ROW LEVEL SECURITY;
ALTER TABLE recommendations ENABLE ROW LEVEL SECURITY;

-- Policy 1: Users can only read their own data
CREATE POLICY "Users can view own profile"
  ON user_profiles
  FOR SELECT
  USING (auth.uid() = id);

CREATE POLICY "Users can view own sessions"
  ON practice_sessions
  FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can view own analyses"
  ON session_analyses
  FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can view own recommendations"
  ON recommendations
  FOR SELECT
  USING (auth.uid() = user_id);

-- Policy 2: Users can insert their own data
CREATE POLICY "Users can insert own sessions"
  ON practice_sessions
  FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can insert own analyses"
  ON session_analyses
  FOR INSERT
  WITH CHECK (auth.uid() = user_id);

-- Policy 3: Users can update their own profile
CREATE POLICY "Users can update own profile"
  ON user_profiles
  FOR UPDATE
  USING (auth.uid() = id);

-- Policy 4: Users can delete their own sessions
CREATE POLICY "Users can delete own sessions"
  ON practice_sessions
  FOR DELETE
  USING (auth.uid() = user_id);
Admin Access for Beta Debugging

-- Create admin role
CREATE TABLE admin_users (
  user_id UUID PRIMARY KEY REFERENCES auth.users(id),
  granted_at TIMESTAMPTZ DEFAULT NOW(),
  granted_by UUID REFERENCES auth.users(id)

-- Admin policy: can read all data
CREATE POLICY "Admins can view all sessions"
  ON practice_sessions
  FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM admin_users 
      WHERE admin_users.user_id = auth.uid()
    )
  );

5. Migration Path: localStorage → Supabase Without Data Loss
Strategy: Dual-write during transition, one-time import
typescript
// 1. Feature flag for migration
const USE_SUPABASE = import.meta.env.VITE_USE_SUPABASE === 'true';

// 2. Abstraction layer (works with both)
interface SessionStorage {
  savePracticeSession(session: PracticeSession): Promise<void>;
  getSessions(userId: string): Promise<PracticeSession[]>;
  saveAnalysis(analysis: SessionAnalysis): Promise<void>;
}

class LocalStorageAdapter implements SessionStorage {
  async savePracticeSession(session: PracticeSession) {
    const existing = this.getSessions(session.userId);
    localStorage.setItem(
      `sessions_${session.userId}`,
      JSON.stringify([...existing, session])
    );
  }
  
  async getSessions(userId: string): Promise<PracticeSession[]> {
    const data = localStorage.getItem(`sessions_${userId}`);
    return data ? JSON.parse(data) : [];
  }
  
  // ... other methods
}

class SupabaseAdapter implements SessionStorage {
  private supabase = createClient(/* ... */);
  
  async savePracticeSession(session: PracticeSession) {
    const { error } = await this.supabase
      .from('practice_sessions')
      .insert({
        user_id: session.userId,
        duration_seconds: session.durationSeconds,
        word_count: session.wordCount,
        filler_word_count: session.fillerWordCount,
        words_per_minute: session.wordsPerMinute,
        transcript: session.transcript,
        session_type: session.sessionType,
        completed: session.completed
      });
    
    if (error) throw error;
  }
  
  async getSessions(userId: string): Promise<PracticeSession[]> {
    const { data, error } = await this.supabase
      .from('practice_sessions')
      .select('*')
      .eq('user_id', userId)
      .order('created_at', { ascending: false });
    
    if (error) throw error;
    
    // Map DB rows to domain objects
    return data.map(row => ({
      userId: row.user_id,
      durationSeconds: row.duration_seconds,
      wordCount: row.word_count,
      // ... map all fields
    }));
  }
  
  // ... other methods
}

// 3. Factory pattern
function createSessionStorage(): SessionStorage {
  return USE_SUPABASE 
    ? new SupabaseAdapter() 
    : new LocalStorageAdapter();
}

// 4. Use in components

One-Time Migration Script (Run on User's First Login After Supabase Deploy)
typescript
async function migrateLocalStorageToSupabase(userId: string) {
  // 1. Check if migration already done
  const migrationKey = `migrated_to_supabase_${userId}`;
  if (localStorage.getItem(migrationKey)) {
    return;  // Already migrated
  }
  
  // 2. Extract localStorage data
  const localSessions = JSON.parse(
    localStorage.getItem(`sessions_${userId}`) ?? '[]'
  );
  const localProfile = JSON.parse(
    localStorage.getItem(`profile_${userId}`) ?? '{}'
  );
  
  if (localSessions.length === 0) {
    // Nothing to migrate
    localStorage.setItem(migrationKey, 'true');
    return;
  }
  
  // 3. Batch insert to Supabase
  const supabase = createClient(/* ... */);
  
  // Migrate profile
  await supabase.from('user_profiles').upsert({
    id: userId,
    stated_goals: localProfile.statedGoals ?? [],
    focus_areas: localProfile.focusAreas ?? [],
    preferred_session_length: localProfile.preferredSessionLength
  });
  
  // Migrate sessions (batch)
  const sessionsToInsert = localSessions.map(s => ({
    user_id: userId,
    created_at: s.timestamp,  // Use original timestamp
    duration_seconds: s.durationSeconds,
    word_count: s.wordCount,
    filler_word_count: s.fillerWordCount,
    words_per_minute: s.wordsPerMinute,
    transcript: s.transcript,
    session_type: s.sessionType ?? 'free_practice',
    completed: true
  }));
  
  const { error } = await supabase
    .from('practice_sessions')
    .insert(sessionsToInsert);
  
  if (error) {
    console.error('Migration failed:', error);
    throw error;
  }
  
  // 4. Mark migration complete
  localStorage.setItem(migrationKey, 'true');
  
  // 5. Optional: Clear localStorage (or keep as backup)
  // localStorage.removeItem(`sessions_${userId}`);
  
  console.log(`Migrated ${localSessions.length} sessions to Supabase`);
}

// Run on app mount
useEffect(() => {
  if (user && USE_SUPABASE) {
    migrateLocalStorageToSupabase(user.id);
  }
}, [user]);
