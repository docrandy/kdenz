D) Session Engine and Behavior Differences
15. Session Modes
Three modes + baseline, all converging on the same runtime engine:

Mode	Config Flag	Duration	Purpose
Filler	focusMode: "filler"	User-selectable	Filler word awareness
Pace	focusMode: "pace"	User-selectable	WPM monitoring
Technique	focusMode: "filler" + techniqueContext.techniqueId	Technique-defined	Guided technique practice
Baseline	focusMode: "filler" + isBaseline: true	Fixed 180s	Initial calibration
Selection happens via route path + location state. Mode is not a separate field — it's inferred from the combination of focusMode, isBaseline, and techniqueContext.

16. Do Different Skills/Scenarios Change Engine Behavior?
No. The core engine is mode-agnostic. What changes is only UI copy and routing:

Filler detection (word list)	Yes
Filler reconciliation (acoustic + transcript)	Yes
WPM calculation	Yes

E) Persistence and Session History
19. What Is Persisted
Three-tier storage architecture:

Tier 1 — Session Summaries (localStorage voicelab_sessions, 30-day auto-prune):

id, timestamp, date, durationSeconds, wordCount, wpm, fillerCount, fillerRate, focusMode, is_baseline, pauseRate
Saved in sessionStorage.ts via saveSession()
Tier 2 — Full Session Details (sessionStorage voicelab_last_session, tab-lifetime only):

All Tier 1 fields PLUS: audioData (base64), transcript, fillerEvents[], wordTimings[], reconciledFillers[], averageConfidence, lowConfidenceSegments, qualityWarnings[], techniqueId/Name/Prompt
Saved in practiceSessionStore.ts
Tier 3 — Baseline (localStorage voicelab_baseline, persistent, single record):

wpm, fillerRate, fillerCount, pauseRate, wordCount, durationSeconds, timestamp
Saved in baselineStorage.ts
Audio is NOT persisted permanently. It exists only in sessionStorage (cleared on browser close).

F) Coaching / Insights
22. AI Summary
Component: AISummary.tsx
Service: geminiService.ts

Trigger: Auto-fires when the Coaching tab is first viewed in PostSessionResults (PostSessionResults.tsx:109-120). Conditions: phase="results", tab="coaching", not baseline.

API: POST https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent with API key as query param.

Key storage: localStorage voicelab_gemini_key. User enters key manually via password input in AISummary component. Format validated: 30+ chars, alphanumeric.

Prompt: Evaluates delivery, clarity, structure, engagement. Returns 3-part format: "What worked well", "Area to improve", "Quick tip".

Fallback: If no key or API error → formatLocalSummary() from localStatsFormatter.ts generates templated summary from metrics. Badge changes from "AI Generated" to "Local Analysis".

23. Post-Session Insights
PostSessionResults (PostSessionResults.tsx) runs a 4-phase sequential flow:

Self-Assessment — Pre-metrics reflection ("How aware were you?"), 5-point scale. Skipped for baseline.
Results — 3-tab interface:
Coaching — AI summary (CardCarousel with numbered coaching points)
Voice Analytics — MetricCards (WPM, filler rate with baseline delta), WeeklyTrendChart (7-day line chart), transcript confidence indicator
Transcript — Audio playback with filler markers + full transcript with highlight toggle (fillers or pace)
Implementation Intention — When/then commitment format ("When I [trigger], I will [action]"). Skipped for baseline.
Complete — Summary stat + "Practice Again" / "Back to Dashboard" CTAs
TechniqueFeedback (TechniqueFeedback.tsx) skips self-assessment and intention phases. Shows 3 tabs with technique-specific success criteria checklist and common mistakes in the Coaching tab.

24. Audio Playback
Yes, playback is supported — but only immediately after a session.

Capture: useAudioCapture() records via MediaRecorder → Blob → converted to base64 data URL via FileReader.readAsDataURL() in practiceSessionStore.ts:4-13.

Storage: sessionStorage voicelab_last_session.audioData (tab-lifetime only).

UI: AudioPlayback.tsx renders in the Transcript tab of PostSessionResults when sessionData.audioData exists:

Play/pause button (accent teal circle)
Scrub bar with yellow filler markers at detected timestamps (clickable to seek)
Speed controls: 0.75x, 1x, 1.25x
Duration/progress display
Limitation: Audio is NOT available in historical session detail (/session/:id) because it's stored in sessionStorage, not localStorage.

H) Enterprise-Ready "Single User Now" Decisions
28. Top 3 Modularity Priorities
1. Authentication Boundary

Currently: No user concept. All localStorage keys are global (voicelab_sessions).
Keep modular: Create src/services/auth/userContext.ts with getUserStorageKey(baseKey) that returns the key as-is for v1.0 and prefixes with user_{id}_ for v2.0. All storage services call through this.
2. Persistence Boundary

Currently: ~15 files call localStorage.setItem/getItem directly.
Keep modular: Create src/core/persistence/ with a PersistenceProvider interface (save, load, query, delete). v1.0 uses LocalStorageProvider. v2.0 swaps to APIProvider via env var REACT_APP_PERSISTENCE_MODE. Zero UI changes.
3. Analytics Boundary

Currently: No event tracking, only Gemini API calls.
Keep modular: Create src/services/analytics/ with AnalyticsProvider interface. v1.0 uses ConsoleAnalytics (dev) or NoOpAnalytics. v2.0 swaps to Segment/API provider. Wire into session completion, feature views, skill unlocks.
29. Cleanest localStorage → Backend Migration
Insert point: Create the PersistenceProvider interface described above. Then mechanically refactor each service file:

Files to touch (6 total):

src/services/sessionStorage.ts
src/services/baselineStorage.ts
src/features/profile/profileStorage.ts
src/features/labeling/labelingStorage.ts
src/features/accusation-audit/auditStorage.ts
src/services/settingsStorage.ts
Pattern: Change localStorage.getItem(key) → await persistence.load(collection, id). Functions become async. React hooks wrap calls in useEffect with async loader.

Migration path: local → dual-write (write to both, read from API) → api (API only). Controlled by a single env var. Zero UI component changes.
