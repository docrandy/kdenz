Your question hits a critical tension in behavioral intervention design: how to honor user autonomy (Constraint 2: Desire) while delivering what the system diagnoses they need.

The VCM framework provides precise guidance here: Constraint 2 (Desire/autonomous motivation) must remain non-zero, or the entire volitional chain breaks. Your 2:1 or 3:1 ratio approach directly addresses this—keeping the user's intrinsic motivation engaged while strategically introducing system-recommended exercises.

2. How Consumer Products Balance User Choice vs. System Diagnosis
Duolingo's Approach
Strategy: Hidden diagnostic, user-perceived autonomy

User sees: Skill tree with locked/unlocked paths, "Continue" button for recommended lesson

System does:

Tracks P(mastery) per skill via Bayesian Knowledge Tracing

Recommends next lesson based on spaced repetition + diagnostic gaps

But frames it as "suggested for you" (not "you failed X, fix it")

Key insight: Users follow 80%+ of suggestions when framed as personalized optimization, not remediation.

VCM connection: Preserves Constraint 2 (Desire) by avoiding "you're broken" framing. Users feel autonomous even following system path.

Headspace's Meditation Recommendation System
Strategy: Blend user mood selection with diagnosed stress patterns

User chooses: "I'm feeling anxious today" (self-reported state)

System injects: 2-3 sessions targeting anxiety + 1 session targeting diagnosed pattern (e.g., poor sleep hygiene detected from usage logs)

Framing: "Based on your recent sessions, this might help too"

Ratio: Roughly 2:1 (user mood : system pattern)

VCM connection: Honors immediate felt state (C2 Desire) while addressing diagnosed constraint failures (e.g., C6B Maintenance if they abandon sessions frequently).

Calm's "Daily Calm" + "Personalized Recommendations"
Strategy: Anchor + adaptive recommendations

Daily Calm: Single universally recommended 10-min session (everyone gets the same one daily)

For You section:

60% aligned to user's explicitly chosen topics (sleep, anxiety, focus)

40% based on behavior patterns (e.g., suggest morning sessions if user only does evening)

VCM connection: The anchor (Daily Calm) provides structure (C4 Intention), while personalized recs balance C2 (user topics) with C3 (system observes they avoid effortful morning sessions).

3. Simplest Adaptive Implementation (MVP)
Rule-Based Recommendation Engine (Start Here)
typescript
function generateRecommendations(
  user: User,
  session: SessionData,
  diagnosis: DiagnosticResult,
  profile: UserRecommendationProfile
): Recommendation[] {
  
  const recs: Recommendation[] = [];
  
  // 1. Get user-aligned exercises (what they want to practice)
  const userGoals = user.statedGoals;  // e.g., ["public_speaking", "confident_tone"]
  const userAlignedExercises = getExercisesForGoals(userGoals);
  
  // 2. Get system-diagnosed exercises (what they actually need)
  const systemDiagnosedExercises = getExercisesForConstraint(
    diagnosis.failedConstraint,
    diagnosis.rootCause
  );
  
  // 3. Determine ratio based on user's acceptance history
  const targetRatio = profile.optimalUserAlignedRatio;  // Default 0.67 (2:1)
  const totalRecs = 3;  // Always show 3 exercises per session
  
  const numUserAligned = Math.round(totalRecs * targetRatio);  // 2
  const numSystemDiagnosed = totalRecs - numUserAligned;      // 1
  
  // 4. Build user-aligned recommendations
  for (let i = 0; i < numUserAligned; i++) {
    const exercise = selectBestUserAlignedExercise(
      userAlignedExercises,
      profile,
      recs  // Avoid duplicates
    );
    
    recs.push({
      exerciseId: exercise.id,
      recommendationType: 'USER_ALIGNED',
      sourceRationale: { type: 'user_goal', userGoal: userGoals[0] },
      presentationStyle: 'SUBTLE',  // No explanation needed—it's what they asked for
      presentationCopy: {
        title: exercise.name,
        description: exercise.shortDescription
      }
    });
  }
  
  // 5. Build system-diagnosed recommendations
  for (let i = 0; i < numSystemDiagnosed; i++) {
    const exercise = selectBestSystemExercise(
      systemDiagnosedExercises,
      profile,
      recs
    );
    
    // A/B test presentation style per user
    const style = profile.preferredPresentationStyle 
      ?? randomAssignStyle(user.id);  // Assign once, stick with it
    
    const copy = style === 'SUBTLE' 
      ? getSubtleCopy(exercise, diagnosis)
      : getLightExplanationCopy(exercise, diagnosis);
    
    recs.push({
      exerciseId: exercise.id,
      recommendationType: 'SYSTEM_DIAGNOSED',
      sourceRationale: { 
        type: 'diagnostic_failure', 
        diagnosticResult: diagnosis 
      },
      presentationStyle: style,
      presentationCopy: copy
    });
  }
  
  // 6. Randomize order (don't always put system rec last)
  return shuffle(recs);
}

function getSubtleCopy(
  exercise: Exercise, 
  diagnosis: DiagnosticResult
): PresentationCopy {
  // No explicit rationale—just frame as personalized suggestion
  return {
    title: exercise.name,
    description: exercise.shortDescription,
    // NO rationale field
  };
}

function getLightExplanationCopy(
  exercise: Exercise, 
  diagnosis: DiagnosticResult
): PresentationCopy {
  // Brief, non-judgmental explanation
  const rationales = {
    'C1': "We noticed hesitation patterns in your voice. This exercise builds confidence.",
    'C2': "Your energy dipped mid-session. This helps sustain motivation.",
    'C3': "You mentioned effort concerns. This makes practice feel lighter.",
    'C4': "Planning ahead helps—this structures your next session.",
    'C5': "Staying focused can be tough. This strengthens your attention.",
    'C6A': "Getting started is half the battle. This makes initiation easier.",
    'C6B': "Finishing strong matters. This builds your follow-through."
  };
  
  return {
    title: exercise.name,
    description: exercise.shortDescription,
    rationale: rationales[diagnosis.failedConstraint!]
  };
}
4. Multi-Armed Bandit vs. Rule-Based for Style Testing
For Small User Base (<500 users): Use Simple A/B with Delayed Learning
Why:

MAB requires dozens of trials per user to converge

With small N, you want deterministic assignment so you can analyze cohorts

Simpler to debug and explain

Pattern:

typescript
function assignPresentationStyle(userId: string): 'SUBTLE' | 'LIGHT_EXPLANATION' {
  // Deterministic hash-based assignment (user always gets same style)
  const hash = hashUserId(userId);
  return hash % 2 === 0 ? 'SUBTLE' : 'LIGHT_EXPLANATION';
}

// After 10 sessions per user, analyze cohorts
function analyzeStyleEffectiveness() {
  const subtleUsers = users.filter(u => u.assignedStyle === 'SUBTLE');
  const explainUsers = users.filter(u => u.assignedStyle === 'LIGHT_EXPLANATION');
  
  const subtleAcceptance = mean(subtleUsers.map(u => u.acceptanceRate));
  const explainAcceptance = mean(explainUsers.map(u => u.acceptanceRate));
  
  // Pick winning style, apply to all new users
  if (explainAcceptance > subtleAcceptance + 0.05) {
    defaultStyle = 'LIGHT_EXPLANATION';
  }
}
For Larger User Base (>1000 users): Use Contextual Bandit
Why:

Can personalize style based on user context (constraint type, session number, time of day)

Learns faster than pure A/B

Pattern: Thompson Sampling

typescript
interface StyleArm {
  style: 'SUBTLE' | 'LIGHT_EXPLANATION';
  successes: number;  // Accepted recommendations
  failures: number;   // Ignored recommendations
}

function selectStyleThompsonSampling(
  user: UserRecommendationProfile,
  constraint: ConstraintID
): 'SUBTLE' | 'LIGHT_EXPLANATION' {
  
  const arms: StyleArm[] = [
    { style: 'SUBTLE', successes: 1, failures: 1 },          // Prior
    { style: 'LIGHT_EXPLANATION', successes: 1, failures: 1 } // Prior
  ];
  
  // Add user's historical data for this constraint
  const history = user.constraintReceptivity.get(constraint);
  if (history) {
    // Arm 0: SUBTLE
    arms[0].successes += history.subtleAccepted ?? 0;
    arms[0].failures += history.subtleIgnored ?? 0;
    
    // Arm 1: LIGHT_EXPLANATION
    arms[1].successes += history.explainAccepted ?? 0;
    arms[1].failures += history.explainIgnored ?? 0;
  }
  
  // Sample from Beta distributions
  const samples = arms.map(arm => 
    sampleBeta(arm.successes, arm.failures)
  );
  
  // Pick arm with highest sample
  const bestIdx = argmax(samples);
  return arms[bestIdx].style;
}
Recommendation: Start with simple A/B for first 200-500 users, then switch to contextual bandit once you have baseline acceptance rates per constraint.

Exercise preferences	10-15 sessions	Which exercises user completes vs. abandons
Optimal ratio (user:system)	15-20 sessions	Whether user needs 2:1, 3:1, or 1:1
Constraint-specific receptivity	20-30 sessions	Which constraint failures user is willing to address

function getColdStartRecommendations(
  user: User,
  diagnosis: DiagnosticResult
): Recommendation[] {
  
  // Session 1-2: 100% user-aligned (build trust, establish Constraint 2)
  if (user.sessionCount <= 2) {
    return getExercisesForGoals(user.statedGoals, count: 3);
  }
  
  // Session 3-5: Introduce 3:1 ratio (3 user : 1 system)
  if (user.sessionCount <= 5) {
    return [
      ...getExercisesForGoals(user.statedGoals, count: 2),
      ...getExercisesForConstraint(diagnosis.failedConstraint, count: 1)
    ];
  }
  
  // Session 6+: Move to 2:1 (learned ratio)
  return generateRecommendations(user, diagnosis, profile);
}
VCM insight: The cold start mirrors Gate A (Readiness to Choose). First establish C2 (Desire)—prove the system gives them what they want—before introducing C3 (Will/effort acceptance) via system-diagnosed exercises.

6. Ignored Recommendation Handling
Never-Repeat Policy
typescript
interface IgnorePolicy {
  threshold: number;  // Ignore N times → blacklist
  cooldownPeriod: number;  // Days before re-offering
}

const IGNORE_POLICY: IgnorePolicy = {
  threshold: 2,  // Ignore twice → never suggest again
  cooldownPeriod: 30  // Unless 30 days pass
};

function shouldOfferExercise(
  exercise: ExerciseID,
  profile: UserRecommendationProfile
): boolean {
  
  const pref = profile.exercisePreferences.get(exercise);
  if (!pref) return true;  // Never offered before
  
  // Check ignore count
  const ignoreCount = pref.timesRecommended - pref.timesAccepted;
  if (ignoreCount >= IGNORE_POLICY.threshold) {
    
    // Check cooldown
    const daysSinceLastOffer = daysBetween(pref.lastRecommended, now());
    if (daysSinceLastOffer < IGNORE_POLICY.cooldownPeriod) {
      return false;  // Still in cooldown
    }
    
    // Cooldown expired—allow one more try
    return true;
  }
  
  return true;  // Under ignore threshold
}

function handleIgnoredExercise(

  targetConstraint: ConstraintID,
  profile: UserRecommendationProfile

  // If user ignores direct C3 (Will/effort) exercise,
  // offer easier "bridge" exercise that builds toward C3
  
  const bridgeExercises = {
    'C3': [
      'micro_commitment_1min',  // Easier than full effort exercise
      'effort_reframing_game'
    ],
    'C5': [
      'distraction_awareness',  // Easier than full goal-shielding
      'mini_focus_session'
    ]
  };
  
  return selectBestExercise(
    bridgeExercises[targetConstraint],
    profile
  );
}
VCM insight: If user repeatedly ignores C3 (effort-cost) exercises, their EVC computation may be accurately concluding "not worth it." Don't force it—offer lower-effort alternatives or focus on other constraints.

Summary: Practical Implementation Path
Start simple: Rule-based 2:1 ratio (user:system) for all users

A/B test presentation: Assign half to SUBTLE, half to LIGHT_EXPLANATION

Track responses: Log every recommendation + user action in schema above

Learn thresholds: After 10 sessions/user, identify:

Winning presentation style

Exercises with <20% acceptance → blacklist

Users who need 3:1 vs 1:1 ratio

Adapt per user: Move to personalized ratios and contextual bandit for style

Respect autonomy: Never force system recs beyond 50% (preserve C2 Desire)

The VCM-grounded rule: If your system-diagnosed recommendations consistently get ignored (3+ times), the user's volitional system is telling you their EVC is negative for those exercises. Either the exercises are too effortful (C3 failure), or they don't believe they'll work (C1 failure). Don't push harder—diagnose why they're rejecting and offer alternative paths.
