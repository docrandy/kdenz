## Phase Goal

Full AI-powered practice sessions that act as a **biofeedback mirror** — making the
invisible visible in both directions:

1. **Receiving channel**: What was beneath the character's words (already in Phase 20)
2. **Sending channel**: What the user's communication is signaling that they don't realize
3. **Self-identification**: Naming the user's default communication pattern so they can
   build a targeted practice plan around it
4. **Institute connection**: Routing the user to personalized Institute curriculum based
   on their identified pattern and stated aspirations

The session debrief is not a scorecard. It's a mirror: "Here's who you are as a
communicator right now. Here's the gap between that and who you want to be. Here's
your next step."

---

## Platform Architecture Connection

This phase is where the five pillars begin to converge:

- **Voice Practice Lab** → voice biofeedback (sending channel, voice dimension)
- **Skills Lab** → perception biofeedback (receiving channel, subtext dimension)
- **This phase** → full simulation + pattern identification + sending/receiving integration
- **Institute (University)** → personalized curriculum routed by diagnosed pattern + aspiration
- **VCM Diagnostics** → explains WHY the gap persists (which gate is failing)

**Critical constraint from CLAUDE.md:**
"Diagnose internally, intervene externally — users never see gate labels, constraint
numbers, or failure diagnoses. They see contextually appropriate nudges and exercises."

The pattern name ("Surface Reader," "Hedger") IS user-facing — it's a useful label,
not a clinical diagnosis. VCM gate analysis is internal only.

---

## Key Design Decisions (Locked)

1. **Biofeedback mirror is the product identity** — not a training app, not a quiz
2. **Pattern names are user-facing** — they help users identify themselves and plan
3. **Institute curriculum is personalized in sequence, not content** — same library,
   different prescribed path based on pattern + aspiration
4. **Self-identification precedes prescription** — you can't build a targeted plan
   without knowing your current location
5. **The aspiration gap is concrete, not abstract** — translate "FM DJ voice" to
   measurable behavioral markers that the platform can track over time
6. **Session debrief = pattern name + growth edge + one next step** — not a wall of data

## Research Questions for Research Agents

The following questions MUST be investigated before planning begins.
Each is a discrete research task suitable for a parallel agent.

### Research Agent 1: Communicator Pattern Taxonomy

**Question:** What are the established failure-mode categories in communication
coaching, negotiation training, NVC, MI, and CBT literature? How have practitioners
named and described the default patterns people fall into?

**Specifically investigate:**
- What patterns does Voss training identify as common failure modes?
- What does NVC literature say about the ways people avoid emotional contact?
- What does MI (Motivational Interviewing) call the common counselor failure modes
  that apply equally to everyday communication? (e.g., righting reflex, premature
  problem-solving)
- What does CBT say about communication avoidance patterns?
- Are there cross-framework pattern categories that show up consistently?
- How have executive coaches and communication coaches operationalized pattern types
  for their clients?

**Desired output:** A draft pattern taxonomy of 6-10 communicator types with:
- Name (user-facing, non-clinical)
- Signal behaviors (what they do that's observable)
- Root cause (what it costs them)
- Prescribed intervention (what kind of practice closes the gap)
- Institute content type most relevant to this pattern

### Research Agent 2: Voice/Tone Aspiration Framework

**Question:** How do voice coaches, communication trainers, and presence coaches
define and operationalize voice identity archetypes? How do practitioners translate
aspirational identities ("FM DJ voice," "boardroom authority," "warm connector") into
concrete, measurable behavioral targets?

**Specifically investigate:**
- What are the common voice identity archetypes that voice coaches work with?
- How do speech-language pathologists and voice coaches measure progress toward a
  target voice quality? What are the measurable dimensions?
- What prosodic features (pace, pitch variation, energy, resonance, pause patterns)
  correspond to different perceived qualities (authority, warmth, confidence, calm)?
- How does Hume's prosody API output map to these perceived qualities?
  (Investigate Hume's emotion + prosody dimensions: energy, positivity, dominance, etc.)
- What is the minimum viable set of measurable markers that captures the relevant
  dimensions of a "voice aspiration gap"?
- How have apps or platforms successfully translated abstract aspiration ("I want to
  sound more confident") into concrete feedback users can act on?

**Desired output:**
- 5-8 voice/communication identity archetypes (named, described)
- Measurable behavioral markers for each archetype (things Hume or Web Speech can detect)
- A mapping: archetype → key marker gaps → targeted drills/practices
- How to structure the aspiration-setting UX (question set, archetype selection,
  custom description path)

### Research Agent 3: Behavioral Signal Detection from Text + Audio

**Question:** How do you detect specific communication patterns (hedging, rushing,
intellectualizing, avoiding, presumptuous framing) from text transcripts and audio
metadata? What signals are reliably detectable without complex ML?

**Specifically investigate:**
- What linguistic markers reliably indicate hedging? (e.g., "I think," "maybe,"
  "kind of," "perhaps," "right?" as tag questions, softening prefixes)
- What patterns indicate question-ending (seeking validation)?
- What markers indicate intellectualizing vs. empathizing? (content reference vs.
  emotion reference in response)
- What markers indicate rushing or not holding silence?
- What markers indicate presumptuous framing ("you're clearly..." vs. "it seems like...")?
- Which of these are detectable by Gemini from transcript alone?
- Which require audio metadata (pace, pause duration, volume variation)?
- What is the reliable signal-to-noise ratio for each detection method?
- How have existing tools (Hume, Gemini, Web Speech API) been used for pattern
  detection in similar applications?

**Desired output:**
- Signal detection table: pattern → detection method → reliability → data source
- Which signals can be detected from transcript alone (immediate, no Hume needed)
- Which signals require Hume prosody analysis (post-session, async)
- Recommended Gemini prompt structure for pattern detection from transcript
- Edge cases and failure modes for each signal

## Institute (University) Personalization — Architecture Decision

### The Core Principle

The Institute content library is **shared** — every user has access to the same
articles, videos, exercises, and lessons. But the **curriculum path is personalized**
based on:

1. **Diagnosed pattern** — what the user IS as a communicator right now (from session
   debrief)
2. **Stated aspiration** — who they want to become (set in onboarding or profile)
3. **Current skill gaps** — what techniques they haven't mastered yet (from Skills Lab)
4. **VCM gate status** — why the gap persists (internal; surfaces as exercise type
   recommendations, not gate labels)

### What This Means for Building

Every Institute content item needs to be tagged before curriculum routing can work.
The tagging schema must be designed before Institute content is built.

**Proposed tagging schema:**
```typescript
interface InstituteContentItem {
  id: string
  title: string
  type: 'video' | 'article' | 'exercise' | 'quiz' | 'demo' | 'comparison'
  technique_ids: string[]          // which techniques this covers
  addresses_patterns: string[]     // which communicator patterns this helps
  supports_aspirations: string[]   // which voice/comm archetypes this builds toward
  vcm_gates: string[]              // which VCM gates this addresses
  prerequisite_ids: string[]       // what to consume/practice first
  duration_minutes: number
  practice_before_exposure: boolean // true = user should attempt technique first
}
```

**Routing logic (simplified):**
1. User completes session → pattern identified (e.g., "Hedger")
2. System queries Institute items where `addresses_patterns` includes "hedger"
3. Filter by user's current skill level and prerequisites
4. Sort by aspiration alignment
5. Surface top 1-2 items in session debrief with "Why this for you" context
6. Build a prescribed 4-6 item curriculum sequence for the dashboard

### The Debrief → Institute Connection

At the end of every simulation session, the debrief should include:

**"Your next step" section:**
- Pattern name + one-line observation (non-judgmental)
- 1 Institute item surfaced with personal context:
  "You've been hedging your labels. This article shows why the hedge closes the
  space you just opened — and how to drop it. [Read: The Cost of 'Right?']"
- 1 drill recommended: the specific technique most likely to close the gap

This is the moment of highest receptivity — right after the "holy shit moment" —
and the product should capitalize on it.

## Technical Notes for Researchers & Planners

### Gemini Call Architecture (Two Calls Per Exchange)

Phase 20 has one Gemini call per exchange (character response). Phase 20.1 adds:

**Call 1:** Character response (existing from Phase 20)
- Input: character system prompt + subtextLayer + conversation history + state object
- Output: `{ reaction: string, stateUpdate: { mood, trust_level, openness } }`

**Call 2:** Pattern analysis (new in Phase 20.1)
- Input: user's response text + conversation history + pattern detection rubric
- Output: `{ signals: string[], patternNote: string, sessionPattern: string | null }`
- sessionPattern only set after 3+ exchanges with consistent signals
- This feeds Panel B of the two-panel reveal ("What you signaled")

**Call 3 (end of session only):** Session debrief synthesis
- Input: full session history + all pattern notes + aspiration profile
- Output: `{ patternName: string, observation: string, growthEdge: string, nextDrill: string, instituteItem: InstituteContentItem }`

### Cost Estimate
- 2 Gemini calls per exchange × 10 exchanges = 20 calls per session
- 1 debrief call = 1 call
- Total: ~21 calls per session ≈ $0.02-0.04 per session (acceptable at beta scale)

### State Object Evolution (Phase 20 → Phase 20.1)

Phase 20:
```typescript
{ mood, trust_level, openness, last_depth_reached }
```

Phase 20.1 (extended):
```typescript
{
  mood: 'guarded' | 'neutral' | 'opening' | 'open' | 'closed',
  trust_level: number,       // 0-100
  openness: number,          // 0-100
  last_depth_reached: 'missed' | 'surface' | 'underlying' | 'identity',
  concessions: string[],     // what the character has revealed so far
  revelation_stage: number,  // 0-4 (how much of their story has emerged)
  last_tactic_detected: string | null  // what technique the user just applied
}
```

### localStorage Keys (New in Phase 20.1)
- `kdenz:user-aspiration` — user's stated voice/comm identity target
- `kdenz:pattern-history` — session-level pattern observations (rolling 10 sessions)
- `kdenz:institute-progress` — which Institute items consumed, prescribed, completed
