## Decisions Made

- **patternDataRef pattern:** Ref mirrors patternData state so `handleSessionEnd` always reads the latest value even when called from a setTimeout or from `handleFinish` where the closure might be stale.
- **handleSessionEnd replaces both exit paths:** Both the MAX_EXCHANGES auto-end (via setTimeout) and the "Finish" button now call `handleSessionEnd(patternDataRef.current)` — unified path.
- **GrowthEdgeCard UI owns the "In your next session, try:" prefix:** The `growthEdge` field stores only the behavior (Gemini prompt specifies this). Keeps the framing consistent whether Gemini or fallback generates it.
- **onNextStep stub in ConversationalDrill:** For this plan, clicking "Start" on NextStepCard calls `onComplete`. Full navigation to `/practice/drill/:id` or `/institute/:id` deferred to Institute integration phase.
- **Trajectory `toward_target` trigger:** Session confidence < 0.8 with consistent same-pattern history signals improvement (pattern is weakening). Gemini may override this with its own trajectory assessment.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Used `patternDataRef` to avoid stale closure in async session-end handler**

- **Found during:** Task 2 (wiring handleSessionEnd into ConversationalDrill)
- **Issue:** The plan noted the stale closure risk for patternData in useCallback. If `handleSessionEnd` closed over `patternData` state directly, it could read an old value (especially since pattern detection is async and state updates are batched).
- **Fix:** Added `patternDataRef` that is updated synchronously inside each `setPatternData` call. `handleSessionEnd` receives `patternDataRef.current` explicitly — always fresh.
- **Files modified:** `src/features/labeling/ConversationalDrill.tsx`
- **Committed in:** `eefa9a8` (Task 2 commit)
