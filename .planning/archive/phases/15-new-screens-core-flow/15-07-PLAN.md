<task type="auto">
  <name>Task 1: Fix SessionOrb disabled prop causing desaturated appearance</name>
  <files>src/components/PracticeSession.tsx</files>
  <action>
The SessionOrb on line 122-127 of PracticeSession.tsx always passes `disabled` prop:

```tsx
<SessionOrb
  audioLevel={metrics.audioLevel}
  isRecording={!lifecycle.isPaused}
  onClick={() => {}}
  disabled
/>
```

The CSS `.session-orb-wrapper.disabled` applies `opacity: 0.5; filter: brightness(0.8) saturate(0.5)` which desaturates the gold gradient, making it look washed out / not gold.

Fix: Remove the `disabled` prop. The orb should show at full gold vibrancy during recording. The `onClick={() => {}}` already makes it a no-op. If click prevention is still desired, keep `onClick` as no-op but do NOT pass `disabled` -- the visual degradation is the problem.

Change to:
```tsx
<SessionOrb
  audioLevel={metrics.audioLevel}
  isRecording={!lifecycle.isPaused}
  onClick={lifecycle.handleStop}
  disabled={false}
/>
```

Note: Setting `onClick={lifecycle.handleStop}` makes the orb functional as a stop button (tapping orb = stop, per Phase 13 SessionOrb design where stop = square overlay on orb). If the intent is for the orb to be display-only during recording, use `onClick={() => {}}` with `disabled={false}` instead. The critical fix is `disabled={false}` (or simply omitting `disabled`) so the CSS desaturation does not apply.

Per user decision (SCR-04): "Stop = square overlay on orb (already implemented in Phase 13)" -- so `onClick={lifecycle.handleStop}` is the correct behavior.
  </action>

Run `npm run build` to confirm no TypeScript errors. Visually inspect: SessionOrb should NOT have the `.disabled` class applied during recording, confirming full gold gradient visibility.
  </verify>

Root cause: PreSessionScreen.tsx (line 44-49) passes free practice route state as:
```tsx
navigate(`/practice/${mode}`, {
  state: {
    durationSeconds: selectedDuration,
    speakingPrompt: selectedPrompt,  // SpeakingPrompt OBJECT (not string)
  },
});
```

But PracticeSession.tsx (line 37-39) reads:
```tsx
const practicePrompt = (location.state as any)?.practicePrompt as string | undefined;
```

TWO bugs here:
1. Wrong key: reads `practicePrompt` but free practice sends `speakingPrompt`
2. Wrong type: `speakingPrompt` is a `SpeakingPrompt` object `{ id, title, category, duration, prompt, tips? }`, not a string. The display text is in `.prompt`.

Fix in PracticeSession.tsx:

1. Add import for SpeakingPrompt type:
```tsx
import { SpeakingPrompt } from "../data/speakingPrompts";
```

2. Read the speaking prompt from route state (add after the existing `techniqueName` read on line 40-42):
```tsx
const speakingPrompt = (location.state as any)?.speakingPrompt as SpeakingPrompt | undefined;
```

3. Compute a unified display prompt string that works for both technique practice AND free practice:
```tsx
// Resolve display prompt: technique practicePrompt (string) OR speakingPrompt.prompt (from object)
const displayPrompt = practicePrompt || speakingPrompt?.prompt;
```

4. Update the practice prompt rendering block (around line 129-136). Change `{practicePrompt && (` to `{displayPrompt && (` and use `displayPrompt` in the paragraph:

```tsx
{/* Practice/speaking prompt - positioned right under SessionOrb */}
{displayPrompt && (
  <div className="max-w-lg mx-auto px-4">
    <p className="text-body-lg text-text-muted text-center">
      {displayPrompt}
    </p>
  </div>
)}
```

This ensures:
- Technique practice mode: `practicePrompt` (string from route state) displays as before
- Free practice mode: `speakingPrompt.prompt` (extracted from object) displays correctly
- No prompt selected: Neither exists, nothing renders (correct behavior)
